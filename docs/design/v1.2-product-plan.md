# Diverge v1.2 开发方案：个人直觉盲区训练闭环

> **版本基线**：`v1.1.15`
> **部署约束**：继续 100% 运行于 Cloudflare Pages 免费层 + 静态托管，**零后端数据库、零账号登录、零用户数据上传**。
> **核心目标**：将 Diverge 从“单盘复盘工具”升级为“**发现直觉盲区 → 看懂后果 → 持续练到不再踩坑**”的个人训练闭环。
> **离线验收标准**：断网重开页面后，错题本读取正常且由本地 Stockfish WASM 实际完成至少一道题的走法判分与 SRS 进度回写。

---

## 1. 版本范围与核心原则

### 1.1 v1.2 核心交付项（按优先级）

| 优先级 | 模块 | 解决的核心痛点 | 新增存储 |
| :--- | :--- | :--- | :--- |
| **P0** | **视角归属与本地档案（Profiles）** | 区分“我的错题”与“对手/名局的错题”；支持同一台电脑分开管理多个棋手（如家长与孩子） | `IndexedDB (diverge_study_v1)` |
| **P0** | **3 步后果快放（Consequence Replay）** | 文字解释不够直观，棋手需要亲眼看到“贪吃/顺手走完后 2–3 步怎么出事” | 零新增存储（复用 `verifiedPlayedPv` / `verifiedBestPv`） |
| **P0** | **纯本地直觉错题本 + 间隔重复（Mistake Bank）** | 单盘复盘关掉即忘，缺乏针对“自己踩过的直觉陷阱”的反复重练 | `IndexedDB (diverge_study_v1)` |
| **P1** | **最近 10 盘直觉体检（Intuition Checkup）** | 单盘只能看孤立失误，跨 10 盘才能看清阶段性盲区与直觉分段画像 | `IndexedDB (diverge_study_v1)` |
| **P2** | **单步分歧分享卡片（Shareable Card）** | 发现精彩分歧后一键出图发群/发教练/发社区，形成自然传播 | 零新增存储（纯前端 Canvas 生成） |

### 1.2 硬性工程边界

1. **单一数据主权（避免两头分裂）**：错题本与 10 盘体检**仅在 `https://4chess.cc/analysis/` 工作台提供**（Chrome 扩展与网页的 `IndexedDB` 隔离，扩展端继续通过既有通道将完整棋局导流到工作台）。
2. **与模型缓存严格分库**：学习数据存入独立数据库 `diverge_study_v1`，绝不与 `ModelCache` 混库，避免清理大体积 Maia 权重时误删用户错题。
3. **绝不静默误收**：未明确归属棋手时（如示例名局、观战棋局），绝不自动将着法写入错题本。
4. **Fair-Play 铁律不变**：实时对局及扫描锁定态下禁用所有新功能；`FairPlayGuard` 与 `scanSourceLocked` 保持最高优先级。

## 2. 视角归属与多档案设计（解决“是谁的错题”）

### 2.1 本地档案（Profile）

默认提供一个 `default` 档案，允许用户在错题本顶部切换或新建档案（例如「自己」「孩子」），每个档案独立维护：
- `displayName`：显示名称（如“我”、“儿子”）
- `aliases`：绑定的常用棋手名/ID 列表（如 Chess.com ID、Lichess ID、线下赛记谱名，大小写不敏感、首尾去空格）
- `targetElo`：默认模拟直觉分段（可选，默认跟随工作台 `currentElo`）

### 2.2 三级归属判定规则

任何棋局进入工作台复盘后，通过统一函数 `resolvePerspective(pgnMeta, activeProfile)` 计算当前棋局归属：

1. **确定本人（`white` 或 `black`）**：
   - 来源为「用户名拉取 10 盘体检」：直接匹配输入的用户名，100% 锁定该方。
   - 来源为单盘 PGN / 公开链接：`metaWhite` 或 `metaBlack` 精确命中当前档案的 `aliases`（若仅命中一方则自动锁定该方）。
2. **需要确认（`ambiguous`）**：
   - 批量拖入多盘本地 PGN 时：统计所有 PGN 中出现频次最高的棋手名，弹出轻确认框：“以 **[最高频棋手名]** 的视角生成体检并收录错题？（可切换白/黑或输入别名并顺手保存）”。
3. **旁观 / 研究模式（`spectator`）**：
   - 示例棋局（Fischer / Kasparov）、单 FEN 局面、或双方均未命中 `aliases`。
   - **行为约束**：不显示“一键批量收入本局全部陷阱”，但每张直觉陷阱卡片保留显式的 **「+ 收入错题本」** 按钮（默认以该步走棋方作为练习视角，供用户主动收藏经典局面）。

## 3. 存储设计（纯本地 `IndexedDB` + JSON 备份）

### 3.1 数据库结构：`diverge_study_v1`

```js

{
  id: 'default',              // UUID 或 'default'
  displayName: '默认档案',
  aliases: ['keluoke'],       // 规范化为 lowercase 匹配
  createdAt: 1763400000000,
  updatedAt: 1763400000000
}

// Store 2: traps (keyPath: 'id', indexes: ['by_profile_due', 'by_profile_created'])
{
  id: '<profileId>|<fenBefore>|<playedUci>', // 同档案同局面同错步自动去重
  profileId: 'default',
  fenBefore: '...',
  turn: 'w',                  // 'w' | 'b'
  moveNumber: 17,
  playedUci: 'c3d1',
  playedSan: 'Nxd1',
  bestUci: 'c8e6',
  bestSan: 'Be6',
  playedPv: ['c3d1', '...'],  // 最长 3 步，供快放复用
  bestPv: ['c8e6', '...'],    // 最长 3 步
  maiaTopSan: 'Nxd1',
  elo: 1900,
  humanProb: 0.331,
  eslLoss: 14.2,              // verifiedExpectedScoreLoss
  lossCp: 165,                // verifiedLossCp
  phase: 'middlegame',        // 'opening' | 'middlegame' | 'endgame'
  source: {
    white: 'Byrne',
    black: 'Fischer',
    result: '0-1',
    date: '1956.10.17',
    url: ''                   // 可选，公开对局链接
  },
  srs: {
    stage: 0,                 // 0..4，对应间隔 [1d, 3d, 7d, 14d, 30d]
    nextReviewAt: 1763486400000,
    streak: 0,
    attempts: 0,
    lastStatus: 'new',        // 'new' | 'independent' | 'hinted' | 'revealed' | 'attempted'
    lastReviewedAt: null
  },
  createdAt: 1763400000000
}

// Store 3: checkups (keyPath: 'id', indexes: ['by_profile_created'])
{
  id: '<uuid>',
  profileId: 'default',
  sourceLabel: 'lichess:keluoke', // 或 'local-pgn-batch'
  playerName: 'keluoke',
  gameCount: 10,
  analyzedMoves: 312,
  eloFit: { 1100: 0.41, 1500: 0.56, 1900: 0.62, 2200: 0.49 },
  phaseTraps: { opening: 2, middlegame: 7, endgame: 3 },
  topTrapIds: ['...'],        // 指向 traps store 的前 5 个高损陷阱
  createdAt: 1763400000000
}
```

### 3.2 持久化与备份策略

- **持久化申请**：首次写入错题时异步调用 `navigator.storage?.persist?.()`，降低浏览器自动回收风险。
- **容量与上限**：单条错题约 `0.5 KB`，`traps` 上限可设 `2000` 条/档案（约 `1 MB`），`checkups` 保留最近 `20` 次记录。
- **导入 / 导出备份**：在错题本顶部提供「导出 JSON」与「导入 JSON（按 `id` 合并去重，不覆盖已有更高 `streak` 记录）」，实现零后端跨设备迁移。
- **降级容错**：无痕模式或 IndexedDB 不可用时退化为当前标签页内存存储，并给出轻量提示，不阻塞复盘主流程。

## 4. 各功能模块详细技术方案

### 4.1 P0：3 步后果快放（`analysis/consequence-player.js`）

**触发位置**：
- 右栏直觉陷阱卡片（`.blunder-card`）与 `#review-commentary` 区域新增按钮：**「看后果」**（有 `verifiedPlayedPv.length >= 2` 时显示）。

**交互流程**：
1. 点击「看后果」后，记录当前视角与 `gameEpoch`，取消进行中的 `positionAnalysis` 箭头覆盖。
2. 棋盘定位到 `move.fenBefore`，每步间隔 `750ms` 依次演绎 `verifiedPlayedPv`（最多 3 步：实战错步 → 对手反击 → 后续惩罚），每步同步播放对应音效（`soundEffects.playSoundForMove`）并在状态栏高亮当前演进步。
3. 演完后停顿 `1000ms`，提供两个即时动作：
   - **「看引擎正解」**：自动切回 `fenBefore` 并用同样节奏演绎 `verifiedBestPv` 前 2–3 步；
   - **「返回局面」**（或任意方向键/点击棋盘/切步立即中止快放并恢复原局面）。

**并发与状态守卫**：
- 维护 `playbackGeneration` 与 `app.gameEpoch`；切换棋局、点击记谱、进入分支或开始练习时立即 `stop()` 并清理定时器。

### 4.2 P0：直觉错题本与 SRS 重练（`analysis/study-store.js` + `analysis/mistake-bank.js`）

**收录入口**：
1. **单步收录**：每个已复核的 `intuition_trap` 卡片与 `#review-commentary` 下方提供「收进错题本 / 已收录」切换按钮。
2. **本局一键收录**：当 `resolvePerspective()` 明确识别出本人为白方或黑方且存在未收录的我方已复核陷阱时，在 `ReviewOverview` 弹窗和右栏顶部显示「将本局我的 N 个直觉陷阱收入错题本」。

**错题本界面与训练闭环**：
- 顶栏或右栏新增轻量入口：**「错题本 (N 待练)」**（数字为当前档案下 `nextReviewAt <= now` 的到期题数）。
- 打开错题本面板后支持：
  - 切换/管理档案（配置常用棋手名）；
  - 按状态筛选：**今日待练 / 全部 / 已掌握**，按阶段筛选：**开局 / 中局 / 残局**；
  - 点击**「开始今日练习（最多 5 题）」**直接启动错题重练。

**复用现有 `ReviewPractice`（关键改造点）**：
目前 `analysis/review-practice.js` 的 `showItem()` 依赖 `app.goToPly(this.item.ply, ...)`，强绑定在“当前已加载的一盘棋”上。为了让错题本能直接跨棋局连刷，需要给 `ReviewPractice` 增加 **独立局面模式（Standalone FEN Mode）**：
- `start(item, { queue, mode = 'game', onItemResult })`：
  - `mode === 'game'`：沿用现有逻辑，通过 `goToPly` 切换。
  - `mode === 'bank'`：直接 `app.boardUI.setPosition(item.fenBefore)` 并按 `item.turn` 自动调整棋盘朝向（白走白在下、黑走黑在下），结束后触发 `onItemResult(item, status)` 写回 `IndexedDB`。
- **SRS 更新规则**（简单透明）：
  - `independent`（独立走对）：`stage = Math.min(4, stage + 1)`，`streak++`，按 `[1, 3, 7, 14, 30]` 天推算 `nextReviewAt`。
  - `hinted`（用提示走对）：`stage` 不变，`nextReviewAt = now + 1 天`。
  - `revealed` / `attempted`（看答案或答错）：`stage = 0`，`streak = 0`，`nextReviewAt = now + 12 小时`。

### 4.3 P1：最近 10 盘直觉体检（`analysis/checkup-runner.js`）

**数据获取（零后端）**：
- **Lichess**：直接 `GET https://lichess.org/api/games/user/{username}?max=10&pgnInJson=true&clocks=false&evals=false`（`Accept: application/x-ndjson`），仅保留已完赛标准棋局（过滤 `variant !== 'standard'` 或未终局对局）。
- **Chess.com**：先拉取 `GET https://api.chess.com/pub/player/{username}/games/archives`，取最近 1–2 个月归档 URL，筛选最新 10 盘标准规则完赛 PGN。
- **本地多盘 PGN**：支持一次选择或拖入多个 `.pgn` 文件，或包含多局棋的单个合集 PGN，走高频名确认后分析（上限单次 15 盘以控时）。

**计算预算与体验控制**：
- 为避免 10 盘全深搜耗时过长，体检采用**快速筛选 + 重点深核**策略：
  1. 跳过开局前 6 回合及双方唯一合法着法；
  2. 只对**目标棋手（我方）**的着法跑 Stockfish 轻量初筛（Depth 10）+ Maia 当前 Elo 推理；
  3. 仅对命中疑似直觉陷阱的着法跑深搜复核（Depth 14），同时顺手抽样计算 1100 / 1500 / 1900 / 2200 四个分段的对数似然/Top-1 吻合度；
  4. 全程提供明确进度条（如“第 3/10 盘 · 正在分析中局”）、随时可「取消」并保留已算完棋局的部分报告。
- **开/中/残局划分（纯规则，零成本）**：
  - 开局：`ply <= 16` 或 `isBookMove`；
  - 残局：双方非兵子力总和（不含王，Q=9/R=5/B=3/N=3）`<= 24`（或无后且子力 `<= 30`）；
  - 其余为中局。

**体检报告输出**：
- 摘要卡片：直觉最接近的分段、三阶段陷阱分布柱状条、Top 5 高损直觉陷阱列表；
- 底部两个主操作：**「将 Top 5 陷阱收入错题本」**、**「立即练习这 5 题」**。

### 4.4 P2：单步分歧分享卡片（`analysis/share-card.js`）

- **纯本地渲染**：使用离线 `<canvas>`（输出 `1200×675` 16:9 或 `1080×1350` 竖版供小红书/移动端），复用现有棋子 SVG 与冷蓝（Stockfish）/ 琥珀（Maia）箭头配色。
- **卡片元素**：棋盘局面 + 双箭头 + 顶部一句话标题（如 `1900 Elo: 33.1% play Nxd1 — Stockfish plays Be6`）+ 底部低调 `4chess.cc` 水印。
- **输出动作**：一键「复制图片（Clipboard API）」或「下载 PNG」，零网络上传。

- 回归与打包检查：
  - 跑通现有全部 26 套测试、`npm run build`（验证 `sw.js` 清单完整）、`npm run test:release`（验证扩展包不包含冗余测试文件且公平竞技守卫无回归）。

### 6.2 真实场景手工验收
1. **父子双档案场景**：建「爸爸」「儿子」两个档案，分别导入各自对局；验证错题本互不串味，切换档案后待练数即时刷新。
2. **示例名局防误收**：打开 Fischer 示例局，确认不出现自动入库提示；手动点单步「+ 收入错题本」后可在错题本中刷到该题。
3. **3 步后果快放**：在直觉陷阱卡片点击「看后果」，棋盘依次走完 2–3 步并有音效，中途按方向键立刻停止且盘面不错乱。
4. **零网络离线复用**：PWA 安装后断网打开工作台，错题本列表、后果快放、基于本地 Stockfish 的错题重练全部正常可用。
5. **备份恢复**：导出 JSON 后清空站点数据，再导入该 JSON，档案与错题进度完整恢复。

## 7. 明确不做的事（Out of Scope）

- 不做用户注册/登录、不做云端多端实时同步（避免引入账号运维、隐私合规与 Cloudflare 付费层依赖）。
- 不做大而全的开局树/棋谱库管理（与 ChessBase / Lichess Study 错位竞争）。
- 不在 Chrome 扩展的实时对局悬浮窗里放错题本或体检入口（严格守住公平竞技边界）。
