# Scan 1.1.2：同步方向与行棋方后处理

日期：2026-10-14。安装包：`releases/diverge-extension-v1.1.2.zip`。

用户样图：[带黑方坐标的静态棋图](https://pbs.twimg.com/media/HPdmqIlXgAAVKHQ?format=jpg&name=small)。

## 定位与修复

- 1.1.1 的识别核心与 chesspuzzle 当前 core 字节一致；原图在两端均识别为黑方视角，坐标置信度 0.96，棋子布局一致。
- 差异在页面后处理：chesspuzzle 的 `image-context.js` / `default-context.js` 会在坐标不足时用棋子分布作为方向默认值，并根据明确轮次、将军、箭头或视角选择行棋方。扩展原来没有接上这两份模块，保留了核心的白方行棋默认值。
- 这两份模块现已按原始源码加入共同的静态构建、源哈希和产物哈希锁，无复制维护的第二套算法。共享包版本 `2026.10.14.2`，构建工具版本 2，源树 `e840c01048bb…`；棋子分类、坐标算法和权重未变。
- 使用原始棋子标签构建可编辑局面；可靠坐标优先，坐标不足时采用与 chesspuzzle 相同的分布默认值。方向变化时可疑格的标记也同步映射。
- 行棋方的明确证据优先于视角默认值。无轮次证据的样图现在默认黑方行棋，但界面明确标为“默认值，待确认”；手动选择保留为用户选择。不会把坐标方向当作确定的轮次识别。
- 中英文展示坐标方向证据、默认行棋方、冲突或用户选择。仍需确认局面才启动 SF，所有来源绑定和公平竞技保护继续生效。

## 实测

- `npm test`：通过，新增同图真实像素回归；断言黑方坐标识别、正确布局、默认黑方行棋但 `turnKnown=false`，以及将军 / 明确轮次证据的优先级。
- 两项目 `sync --source`、邻项目同步脚本和真实 WASM 金样对照：通过，方向 / 轮次核心输出一致，默认值后处理一致。
- 原生 Chrome action popup：同一 JPEG 嵌入 X 信息流结构及普通文章，DPR 2 实际截图、遮罩、本地识别；读取纵坐标 `12345678`，黑方视角 0.96，棋子布局逐格正确。中英文切换后仍显示未确认默认值，确认后真实 SF19 Lite 返回三分支。图片替换后撤销。
- 原有 DOM 来源、popup 重开、升变、网页交接回归：通过；新棋钟触发后 9ms 停机 / 清空。
