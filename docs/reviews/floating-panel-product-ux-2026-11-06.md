# 悬浮窗产品与用户体验评审

日期：2026-11-06。基线：当前工作区源码，HEAD `fc6b376`，manifest 1.1.7。评审前 Git 工作区干净。本次只新增评审文档与本地证据，未修改产品代码、发布包或线上部署。

## 结论

悬浮窗已经具备清晰的产品价值：在允许分析的场景中，让用户比较“引擎认为哪步好”和“Maia 预测棋手更可能走哪步”。玉绿色视觉、三条候选、图例折叠、固定全盘分析入口、真实引擎状态与公平竞技保护，都值得保留。

主要短板集中在空间利用、状态表达和理解成本。当前界面更像把引擎能力装进侧栏，尚未充分围绕用户的三个问题组织：**现在能做什么？这个局面值得关注什么？下一步如何深入复盘？** 建议先解决可用性与可信度，再调整信息层级，无需先做整套视觉重绘或添加更多分析指标。

没有在本次覆盖范围内发现公平竞技绕过。下文涉及保护状态的建议只优化展示与交互，必须继续由现有 FairPlayGuard 决定权限；未知状态仍锁定，实时对局中禁止计算与建议。

## 重点问题与验收条件

### UX-01：先保证正文有空间，再谈自适应

在 250×200 px 组件中，正文 `clientHeight` 只有 **24px**，内容高 463px，一条候选行约 52.6px，初始可见高度为 **0px**。视觉上主按钮与底部引擎状态占了绝大部分空间。现有自动化的“无横向溢出”“按钮可见”均能通过，但用户无法读完一条候选。这是本次最明确的可用性问题。

原因是 `fitPanel()` 接受最低 200px 的广告位，而头部、固定行动与引擎状态继续使用完整模式。[尺寸逻辑](/Volumes/AI/coding/simoextension/content/intuition-panel.js:698)、[固定区域样式](/Volumes/AI/coding/simoextension/content/styles.css:1384)。

建议按正文可用空间选择布局：完整模式展示结论、三条候选及次级状态；精简模式只展示首选对比与“展开详情”；极短区域使用摘要入口并打开可容纳内容的完整面板。若需要继续覆盖原广告位，可将覆盖背景与内容面板分离。具体断点应由中英文、字号放大和状态文案共同决定。

验收：短区域也能完整读到一条核心结论；固定区域不与正文重叠；首选和展开入口可达。新增内容可见高度与区域交叠检查，不能只验证 DOM 可见和外框不溢出。

证据：[250×200 截图](/Volumes/AI/coding/simoextension/artifacts/floating-ux-review-2026-11-06/05-short-slot.png)。

### UX-02：收起需要有明确的空间收益与行为定义

点击右上角收起后，面板仍为 **300×600 px**，原浮球 `display:none`，中央只显示“悬浮窗已收起”。这与代码中的“保留侧栏覆盖”一致，说明原行为有覆盖广告位的目的；但普通用户很难从圆形图标理解这个目的。当前“收起”减少的是内容，空间占用没有减少。[close/hide/open](/Volumes/AI/coding/simoextension/content/intuition-panel.js:641)。

另一个已复现的问题：设置打开时点击收起，`data-collapsed=true`，设置抽屉仍为 `display:flex`，收起页继续被设置覆盖。两个状态没有互斥。

建议保留覆盖广告位能力，同时把行为命名清楚：“收起内容（保留侧栏）”与“最小化”分开；真实最小化变成边缘小入口，隐藏可继续使用扩展菜单。收起或隐藏时统一关闭设置，再根据用户选择恢复。不要为了修复这个问题直接取消已有覆盖能力。

验收：用户能明确识别三种行为；最小化确实释放空间；恢复入口始终在视口内；设置与收起页不会同时占据内容区。图标 tooltip、可访问名称与中英文文案一致。

证据：[收起态](/Volumes/AI/coding/simoextension/artifacts/floating-ux-review-2026-11-06/02-collapsed.png)、[收起后设置仍打开](/Volumes/AI/coding/simoextension/artifacts/floating-ux-review-2026-11-06/03b-collapsed-settings-still-open.png)。

### UX-03：权限正确，也需要界面准确表达

源码 MV3 在平台夹具中复现：

- 大厅或无法确认的棋盘：顶部显示“未启动”，候选区右上仍显示“对局中 · 已锁定”；未知状态收起后又变成“对局进行中”。
- 已确认终局但暂时没有可读取 FEN：保护数据已变成 `false`，全盘按钮可用，但顶部仍是“对局中”、标题仍是“公平竞技保护”、时间区仍是“对局中 · 已锁定”，正文空白。正常棋盘读取得到结果后可能覆盖这些文字；问题在等待与读取失败窗口内持续存在。

这是展示不一致，不是本次发现的守卫失效。解锁分支目前只恢复按钮并删除保护正文，未统一恢复其它标签；收起文案则只看锁定布尔值。[保护状态渲染](/Volumes/AI/coding/simoextension/content/intuition-panel.js:1150)、[收起文案](/Volumes/AI/coding/simoextension/content/intuition-panel.js:678)。

建议展示状态至少分为：等待棋盘、对局保护、状态待确认、已完赛读取中、分析中、部分结果、结果可用、加载失败。权限仍由原守卫控制，不另造允许分析的例外。

推荐表达：大厅“等待棋盘 · 未启动”；未知“正在确认对局状态 · 分析暂停”；实时“对局进行中 · 公平竞技保护”；终局“对局已结束 · 正在读取局面”。锁定页采用一句原因与一句恢复条件即可，原长说明可放帮助中。

验收：展开、收起、刷新、开关设置后使用同一状态；终局解锁不等待引擎首个结果才清除旧文案；下一局仍在铁律规定时限内停机、清除建议并上锁。本次未测量锁定耗时，不能宣称已验收 150ms 指标。

证据：[终局无可读 FEN](/Volumes/AI/coding/simoextension/artifacts/floating-ux-review-2026-11-06/mv3-03-concluded-no-readable-fen.png)、[未知态收起](/Volumes/AI/coding/simoextension/artifacts/floating-ux-review-2026-11-06/mv3-08-unknown-collapsed.png)。

### UX-04：让每种等待和失败都有合适的行动

Maia 正在正常下载、SF 还未给出首个结果时，正文已出现“重试初始化”。这会使正常等待看起来像故障。Maia 加载失败时存在直接重试，并能保留 SF 结果，这个降级方向正确；但 SF 失败时只有底部“启动异常”，没有直接恢复入口。Maia 状态的“加载失败 · 查看设置”也只是文字。[加载/重试分支](/Volumes/AI/coding/simoextension/content/intuition-panel.js:1391)、[引擎状态](/Volumes/AI/coding/simoextension/content/intuition-panel.js:873)。

建议：正常下载显示进度和“首次下载，后续复用缓存”；缓存读取与模型初始化使用不同状态；失败后显示直接重试与切换轻量模型。失败原因用用户可理解的类别表达，技术细节放到展开区。SF 失败允许单独重试，Maia 可用时明确“仅直觉结果，暂无质量评分”；反向情况显示“引擎结果可用，直觉预测尚未就绪”。预估剩余时间只有在有可靠数据时才展示。

验收：正常下载不出现暗示失败的重试；一种引擎失败不会让另一种结果消失；重试具备忙碌反馈和错误闭环；保护状态中不能借重试启动下载或推理。

证据：[正常加载却显示重试](/Volumes/AI/coding/simoextension/artifacts/floating-ux-review-2026-11-06/06-loading.png)、[Maia 失败/SF 可用](/Volumes/AI/coding/simoextension/artifacts/floating-ux-review-2026-11-06/07-maia-failure-sf-ready.png)、[SF 失败](/Volumes/AI/coding/simoextension/artifacts/floating-ux-review-2026-11-06/09-sf-failure.png)。

### UX-05：让用户分得清预测选择率和局面质量

当前候选行同时出现 `59.3%`、`Δ -0.28`、`0.00`；结论出现“局面 +0.32”。详细图例已经正确说明热力图不是胜率，但候选概率与评分没有同样直接的解释。白方视角在格式化函数中存在，界面只写“局面”，黑方用户容易误读。[评分格式化](/Volumes/AI/coding/simoextension/content/intuition-panel.js:987)、[候选行](/Volumes/AI/coding/simoextension/content/intuition-panel.js:1513)。

分歧时还存在数值归属问题：对 Maia 首选的损失被紧接在 `SF19 Lite: d4` 后显示为 `Δ -0.05`，用户可能误以为这是引擎首选 d4 的损失。应把损失明确关联到被评估的 Maia 着法，例如“Maia 首选 e4 · 比最佳低 0.05 兵”。

此外，真实文案是“约 59.3% 的 1900 棋手凭直觉走 e4”。界面展示的是 Maia 预测，当前实现没有附带该局面人群样本量，文案不宜让用户当作真实对局统计。[比较文案](/Volumes/AI/coding/simoextension/engine/maia-engine.js:525)。

建议文案：

- “Maia 预测 · 1900 分段”，列名“选择率”；说明“模型预测的着法选择概率，不是胜率”。
- “白方评分 +0.32”；点击解释“正值对白方有利”。
- “相对最佳损失 0.28 兵”，或保留 `Δ -0.28` 并提供即时说明，避免改变符号规则却不解释。
- 目标等级用“模拟棋手等级”或“目标等级”，避免用户误以为这是自身等级评估；“2200 · 大师段位”可以改成更克制的等级描述。

验收：首次使用者无需离开面板就能区分选择率、评分、评分损失；白方/黑方/将杀局面解释一致；未知损失不能展示为 0；不宣称概率精度已经校准。

## 其它交互与信息架构建议

### 结论优先，减少首屏重复

当前顺序为图例卡 → 结论卡 → 候选 → 固定全盘入口 → 固定引擎状态。默认图例虽然可折叠，仍常驻占据一张卡。共识场景中 e4、59.3%、+0.32 在结论、引擎行、候选行重复出现。共识行的 Δ 0.00 还使用金色背景，与候选行的绿色 0.00 不一致。

建议主屏只保留一个结论，例如“首选一致：e4”，随后展示候选。把“Maia 预测选择率”“相对引擎损失”作为短列名；把目标等级放在候选标题旁。图例移为上下文帮助，首次可有轻提示。正常引擎状态收成一行，下载和错误时展开；型号、WASM、CPU、缓存来源和毫秒耗时放次级详情，精确毫秒不应占据用户理解概率所需的空间。

SF 与 Maia 首选不同并不自动意味着严重错误。当前 `agreed=false` 统一触发金色警告，合成 Δ -0.05 也如此。建议区分“首选不同，评分接近”“存在明显损失”“暂无充分质量比较”，阈值由既有评分规则和评估可靠性决定，不能只看着法是否相同。缺少候选质量评分时要表达未知。

### 设置按任务分层

当前语言、等级预设加滑杆、三种覆盖开关、网页版 SF、三种 Maia 模型、下载说明及指南处于同一长抽屉。[设置结构](/Volumes/AI/coding/simoextension/content/intuition-panel.js:440)。

建议：主屏提供可点击等级与“棋盘显示”；抽屉分“显示”“模型与性能”“语言与帮助”。网页版 SF 可以保留在高级区域，明确标注跳转后的作用，避免它比本窗真正使用的 Maia 模型更靠前。5M/23M/79M 附上“轻量/均衡/更大模型”和首次下载大小，缓存完成后显示“已缓存”；不要在没有质量证据时给大模型冠以“更准确”。切换时区分“已选择”“下载中”“已应用”，而非长期只显示“已保存”。保留现有对局中仅保存偏好的行为。

### 候选预览与可访问性

三条候选使用普通 `div`，`tabIndex=-1`，只有 mouseenter/mouseleave，无法用键盘到达并触发预览；触控也没有等价入口。[候选交互](/Volumes/AI/coding/simoextension/content/intuition-panel.js:1564)。建议使候选具有明确的预览操作，焦点与悬停效果一致；需要触控时用单击预览、再次点击或清除恢复。任何预览仍受同一守卫约束。

当前主题已有 focus-visible 与减少动画设置，值得保留；问题在语义和焦点流。实测三项 checkbox 与 Elo range 都没有关联 label、aria-label 或 aria-labelledby。设置打开后焦点停在外部设置按钮，没有 aria-expanded，Esc 不关闭。建议关联文本和控件，让点击文字也能切换；为选中等级/模型提供选中语义；如果抽屉遮住正文，应防止焦点进入被遮住的操作，关闭后返回触发按钮。顶部按钮实测约 28.5×28px，可在保留视觉尺寸的同时增加命中区。

### 全盘分析的交接闭环

当前按钮点击后用 Toast 显示提取棋谱，没有按钮内忙碌态或防重逻辑；提取不到步数就结束。单局面分析板也显示“全盘分析”，用户点后才知道没有完整棋谱。发送打开消息的回调直接显示成功，没有检查响应或 `chrome.runtime.lastError`。[提取入口](/Volumes/AI/coding/simoextension/content/main-module.js:65)、[成功提示](/Volumes/AI/coding/simoextension/content/main-module.js:239)。

建议可确认有完整棋谱时显示“打开全盘复盘 ↗”；只有单局面时提供“在工作台打开当前局面”，前提是工作台与交接协议明确支持。棋谱可用性未知时允许尝试提取，但失败后提供可执行恢复，例如重试、导入 PGN 或打开空白工作台。点击后按钮显示“正在提取棋谱…”并防止重复触发；收到成功响应后才确认打开。新标签页承接当前等级、语言和选定引擎，实际是否承接成功应另做完整棋谱端到端验收。

### 连续操作、语言与位置

Elo 滑杆的三次键盘递增实测产生 1950、2000、2050 三次回调；主模块每次会调用 `runPrediction`。这证明触发频次，不证明三次计算都完整执行，也没有测得性能损失。建议界面即时更新，计算在拖动结束或短暂停顿后合并触发；同样适用于键盘调整。[滑杆事件](/Volumes/AI/coding/simoextension/content/intuition-panel.js:814)。

计算中切英文，顶部变成 White，但候选标题仍为中文、时间区仍为“计算中…”，顶部丢掉研判中语义。建议保存状态语义，语言变化后完整重绘。[语言处理](/Volumes/AI/coding/simoextension/content/intuition-panel.js:1015)。

拖动只有鼠标事件，标题区没有直观拖动标识，也没有“恢复默认位置”入口。可增加一次性提示、位置重置与键盘可达的停靠方式；以后需要触屏支持时再补 Pointer Events。当前自动广告位跟随、手动位置记忆、视口约束方向正确，调整时需回归不同站点与窗口缩放。

## 建议的主界面结构

推荐完整模式从上到下依次为：

1. 页头：Diverge、明确的局面状态、设置、最小化。
2. 一句结论：首选一致 / 首选不同且评分接近 / 存在值得复盘的损失。
3. 当前对象：白方走；Maia 预测 · 1900 分段，可直接更改等级。
4. 三条候选：着法、预测选择率、相对最佳评分损失；支持预览。
5. 引擎摘要：最佳着法与白方评分，仅一处完整显示。
6. 主行动：打开全盘复盘或打开当前局面；依据可用数据表达。
7. 次级状态：正常时一行；下载、失败与部分可用时展开，直接给恢复操作。

详情说明保留在上下文帮助；下载、保护、未知、错误各自使用专门的内容区，避免在多个角落重复显示不同版本的状态。精简模式只保留状态、核心对比与展开入口。

## 建议实施顺序与验收

第一轮处理 UX-01～UX-05，以及“收起时设置仍开”的交互缺陷。收益是用户能够读到内容、判断插件状态、理解数字并从失败中恢复。沿用现有配色、候选数量、轻量模型默认与守卫。

第二轮整理主屏层级与设置、候选预览、键盘/焦点支持、全盘交接和连续等级调整。第三轮统一计算中的双语表达、位置恢复与细节文案。

每轮除现有回归外，至少验收：

- 250×200、300×600、短窗口与字号放大：核心结论完整可读、固定区无交叠。
- 收起、最小化、隐藏、恢复与设置交叉操作；视口变化后入口可达。
- 无棋盘、未知棋局、实时、已终局但尚无 FEN、关闭终局弹窗、刷新、新局的所有文案和权限一致。
- 下载中、缓存读取、准备模型、Maia 单独失败、SF 单独失败、重试失败、部分结果、恢复成功。
- 键盘可调整等级/开关/候选预览，设置可关闭并恢复焦点；读屏名称需要实际读屏器复核。
- 两种语言、双方走子视角、共识、轻微分歧、明显损失、无可评分候选和将杀分数。
- 有完整棋谱、只有当前局面、提取失败、消息失败、重复点击的工作台交接。
- 公平竞技安全与模型分发铁律全量回归：未知保持锁定；对局中所有入口不可触发建议；大权重仅通过 CDN 与浏览器缓存。

若要度量改版收益，先建立无需上传棋谱/局面内容的基线：允许分析时首次有用结果耗时、失败后恢复成功率、复盘按钮成功交接率、设置操作完成率，以及用户对三种数值含义的理解任务。当前没有这些数值，不据此承诺留存或转化提升。
